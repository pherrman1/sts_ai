# Card fallback objective: bounded source-only diagnosis

Recommendation: a **low-priority, separate ranking hypothesis is technically feasible**, but the historical win-head sweep already failed to confirm a broad advantage. Do not enable STS_CARD_WIN in the fair campaign. No code, game, training or model change was made for this diagnosis.

## Executed routing and information contract

The campaign's V4 card gate runs first. On a declined gate, `serverCardRewardPolicy` ultimately calls `vQuery`; with native OOC on and CARD_WIN/cardNN/cardAction/boss blend off, this immediately calls the app wrapper `nativeFloorCardPick`. That wrapper passes `g_floorNet` and `g_cardSkipThresh=-0.5` to `one_combat::nativeFloorCardPick` in ooc_native_fallback.cpp.

The shared helper is already model-parameterized by `const CompactTreeNet&`. Its `PublicValueScorer` builds one public-history-conditioned K=8 encounter mixture, reuses those scenarios for baseline and every candidate, then averages post-link model predictions. A candidate row adds1 to d(cardId) and deckSize; it does not execute a hypothetical simulator action. It selects the first strict maximum marginal and skips when that marginal is below the threshold. Existing simplifications—offered upgrade state, eggs/card-acquisition relic effects, Singing Bowl skip value and other feature changes—are not corrected by replacing the model.

Current `nativeWinCardPick` used by STS_CARD_WIN also performs feature edits only; it does **not** execute copied simulator transitions or consume actual simulator RNG. Its fairness problem is different and explicit: it calls raw `g_winNet.predict(richFeatureVec(gc))` on the real state and its edited rows, bypassing PublicValueScorer. Thus actual unrevealed encounter features remain available even with STS_OOC_PUBLIC_FUTURES=8. The source hypothesis that STS_CARD_WIN itself requires hypothetical RNG transitions is not supported by this native path. Its legacy server fallback is another reason to avoid simply enabling that broad flag.

Both immutable current models are already loaded in native mode: floor SHA256 `3a3420469b1d648e0e306d6cb6a7e85f3d3499105e3ff3a56eee6c579194ffe3`, win `fc52c14cb7239a33b3c1f9d0477ccb6c895fd51a07240fe804744e605067ad70`. The win file's logistic output can be consumed by the existing public scorer; its post-link averaging is already correct for that head. Reusing it needs no server, new training, map/action simulation or hidden RNG.

## Competing explanations and prior falsification

The attractive explanation is objective mismatch: expected floor can value early survival or tempo while undervaluing the deck that actually wins the final boss. A win head might rank already acceptable cards better. The competing explanation is that the denser floor target supplies more useful local marginal rankings, while the old win head is saturated, noisy, miscalibrated or tied to a weaker historical controller. A model trained on a binary win label is not proof that its counterfactual difference estimates current-policy win probability.

This question has material prior evidence. `docs/experiments/ledger-01.md` section24 records a promising256-seed win-head sweep that did not survive512-seed confirmation: floor47.3% versus win46.5% with win skip-0.02. Section25 reports a512-seed shop-head tie. These are historical configurations, not current-policy or public8 paired evidence, but they directly contradict treating the objective label alone as a new guaranteed improvement. Section20 describes the historic binary-logistic target and stronger HP sensitivity; it does not establish current card-rank calibration. Current negative RestOff/ShopFix development does not itself falsify card-head ranking because those are different decision families, but it reinforces the need to avoid promoting proxy/mechanism intuition.

## Smallest controlled seam and decision rule

A direct model substitution is only one line at the app wrapper, but keeping threshold-0.5 would silently reinterpret floor units as probability units. Replacing it with0 or the historical-0.02 also changes skip behavior. Such a candidate is a declared objective-plus-threshold policy, not a pure head-ranking contrast; do not tune that threshold on this campaign's outcomes.

For the narrowest ranking-only question, keep the baseline's **exact take-versus-skip decision at each reached state**: obtain the ordinary public8 floor pick with threshold-0.5; if it is skip, return skip unchanged; otherwise rank the offered cards with the same shared helper using `g_winNet` and an explicitly nonbinding skip threshold. Use a new strict default-off flag at the app `nativeFloorCardPick` wrapper, not the generic floor-value/shop/removal functions and not STS_CARD_WIN. The repeated scorer construction derives identical scenarios from the same public state, so both heads see matched public futures. No actual GameContext, its RNG, or candidate simulation is involved. V4-owned card decisions remain unchanged under the campaign's margin gate; subsequent states naturally may diverge.

Require native mode, successfully loaded win/floor models, public8, no legacy alternate card family and finite model predictions before enabling. Bind the flag to startup and effective teacher policy. Preserve original models and other decision families. Focused tests should demonstrate unchanged default/off behavior and baseline skip, shared sampled-future invariance under altered private queues/RNG, different legal ranking under a synthetic two-head fixture, exact tie behavior, and zero mutation of source state/RNG. A decision trace should expose head identity, shared-scenario count, floor baseline marginal/skip, win card marginals and chosen semantic key before any whole-run claim.

## Existing decision exposure and limits

The fixed first12 corrected-reference strategic traces contain306 card reward gate decisions:116 owned and190 declined (62.1%). These are roots, not independent runs. The three raw strategic files were independently hashed against their completed wave2 receipts: Fprod_0 `8ac5afb0fd4fc55f5f52a4d50a9bc95a8b96c49c42748adc9060a244b441ee8c`, Fprod_1 `065baa9cd65bd35818733c0eb2bc7ca07d98da68cbfa23d5d997afca7edef6f1`, Fprod_2 `97d7b23adbfc8c705ed3964fe3bee52dfa7dfd37c5e6f7ea64e0ffa33a40f1d5`. No endpoint outcome columns were used for this count. Thus the fallback has enough actual exposure that a ranking-only diagnostic is not obviously inert.

Those strategic qValues belong to V4, not either native GBM; all190 declined roots have heurIdx=-1. Public OOC traces retain offered card IDs/upgrades and inventory transitions, which can identify most realized choices, but do not contain the full native feature/scenario packet or GBM candidate scores. `run_trace.cpp::tr_logDraft` obtains floor marginals from a server-only M endpoint and returns early without a server; it cannot serve as public8 native score evidence. Do not reconstruct missing native scores from compact DECISION features or equate V4 qValues with the fallback's win probabilities.

Within the remaining campaign, this seam is justifiable only as a small explicitly secondary ranking screen after higher-priority supported candidates and reserve constraints. It is not a reason to restart the broad historical skip sweep, change model files, reinterpret existing outcomes or open protected confirmation. The historical null, approximate feature edits and controller mismatch must accompany any result.

## Authorized implementation and source review

The coordinator subsequently authorized the narrow ranking candidate. The new `nativeCardWinRankPick` helper uses a strict default-off `STS_OOC_CARD_WIN_RANK` switch. Off/unset delegates directly to the unchanged floor helper and leaves an optional trace object untouched. Enabled mode requires public8, loaded floor and logistic win models, a valid reward screen/index, and a finite floor threshold. Its floor ranking copies the existing feature edits, first-strict-maximum tie rule and threshold comparison. A floor skip returns immediately without evaluating the win head. Otherwise the same public state/path generates matched scenarios for win ranking, with no win skip threshold. Both heads retain mean-of-post-link predictions. Neither the existing public scorer nor the native floor implementation was changed.

The optional trace records only predictions already required for the decision: floor base and marginals, baseline pick, whether win scores were evaluated, win base and marginals, chosen index and scenario count. All used averaged bases and card marginals must be finite. Checking the base explicitly matters for an empty offer and for arithmetic overflow while accumulating individually finite predictions. This guarantee concerns returned predictions and the existing load-validated model boundary. The compact-tree logistic link can clamp a corrupt in-memory NaN margin; synthetic win rejection fixtures therefore exercise the predictor's explicit cycle-error NaN return, rather than claiming arbitrary corrupt memory validation.

The focused fixture covers exact default/off dispatch, unchanged baseline skip, two-head ranking divergence, all ties and threshold equality, negative win marginals without a new skip, empty offers, shared public scenarios and post-link averaging, altered private seed/RNG/encounter suffix invariance, unchanged source fingerprints, malformed flags, missing/incompatible models, invalid screens/indices/thresholds, nonfinite predictions and finite-value accumulation overflow. These are source-level fixture assertions until the coordinator executes the build/test target; no build or gameplay run was performed by the integrity specialist.
