# Supplementary full-run runtime-health audit

This read-only audit supplements a completed frozen efficacy report. It does not alter its paired win estimates, arm nomination, confirmation decision, or source data. The coordinator authorized initial application only to `wave1_report.json`, `wave2_report.json`, `wave3_report.json` (discovery) and `wave4_removal_report.json`. Development reports still in progress and protected confirmation/TEST data are outside this initial invocation scope. Later application requires the corresponding completed report and exact report SHA256.

`audit_fullrun_health.py REPORT --report-sha256 HASH --out NEW_PATH` refuses output overwrite. It requires `all_pairs_complete=true`, rehashes every report-bound input, verifies manifest and completed receipt identity, and binds each tree/CSV to its invocation prefix. CSV parsing interprets only seed identities. Expected source sets come from the bound manifest, match the report arm counts and CSV shards, and must be represented in each tree. It never globs a gameplay directory or reads an unlisted tree. Tree root identities cannot repeat within a shard.

Endpoint semantics come from `SilverTreeProfile::record` in `src/sim/search/SilverSearcher.cpp`, the emitter `writeTreeProfile` in `NativeSilverBackend.cpp`, and the maintained `architecture/combat-search.md` and `behavior/simulator-health-monitor.md`. Fragment boundaries are respectively `void search::SilverTreeProfile::record` through before `void search::SilverOutcomeCapture::Layer::record`, and `        void writeTreeProfile(` through before `        struct ProfileScope`.

Each endpoint's `tree_depth` and `total_depth` histogram sums must equal its count; all five endpoint counts must equal `completed_simulations`. `heuristic_evaluations` equals that denominator, `neural_evaluations` is zero, and inherited visits are excluded. Total depth cannot sum below tree depth. Rollout-start and cycle counters cannot exceed rollout calls; error-free completed rollout calls cannot exceed completed simulations. Booleans and nonnegative integer fields are checked strictly. Invalid JSON constants, duplicate keys, unknown endpoint classes and malformed histograms fail closed.

The campaign uses10,000 configured simulations, no adaptive mode or learned-stop boss extension. Mode flags are matched to the bound manifest. Flat roots complete10,000; learned roots stop at the compiled checkpoints250,500,1,000,2,000,4,000,8,000,10,000. A singleton skip is allowed only without exact budgets, with one root action and zero new simulations. An error row may contain a partially started rollout and partial budget; its recorded error or abort makes it invalid regardless. The existing `tools/analyze_silver_tree_profile.py` supplies the same conservation semantics but assumes nonadaptive means flat, so direct use would falsely reject learned-stop roots. It is unchanged.

Classification is deliberately separate from efficacy:

- Input custody, allocation or completion failure produces `INVALID_INPUT_CONTRACT`.
- A malformed profile, missing source, duplicate root, nonempty error string, positive descent abort, or unresolved `nonterminal` endpoint produces `INVALID_RUNTIME_HEALTH`. Error rows and all locators remain in the report; no partial root is silently accepted as complete.
- `cycle_rollouts` counts deliberate on-path transposition fallback to an ordinary rollout. It is an expected diagnostic mechanism, not a failure or quality threshold.
- `turn_limit` means simulator loss beyond turn500 and takes precedence over HP. `engine_stop` is another positive-HP simulator loss, including no-damage or loop-guard stops. They are retained separately from sampled deaths and produce `PASS_WITH_DIAGNOSTIC_LIMITS` when no fatal finding exists. The aggregate tree field cannot distinguish these causes, so it does not justify automatically declaring a whole run broken or scientifically clean without interpretation.
- `PASS` establishes this trace-health contract only. It does not establish fairness, calibrated scores, live-game support, or improved win probability.
