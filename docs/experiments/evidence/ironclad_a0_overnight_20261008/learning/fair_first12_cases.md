## Mechanism with strongest new source support

The fallback after a declined V4 campfire gate is not a consistent health-based heuristic. `src/sim/search/ScumSearchAgent2.cpp:165` smiths when HP>50 and an upgrade is legal, rests when HP<15, and otherwise calls `stepRandom`. `GameAction::getAllRestActions` can include RECALL (bits2) based on `gc.keysEnabled`/missing key, independent of `g_collectKeys`; `GameContext::chooseCampfireOption(2)` obtains the Ruby key.

For 610081011 at f12, the strategic trace (CSV despite `.jsonl`) `Fprod_2.strategic.jsonl:197` offers bits0|1|2. Q is84.997|84.6851|81.0403; margin0.311867<1, owned0, takeIdx−1. The public OOC transition changes no visible HP/deck/relic/potion state at40/101HP, and the f15 menu no longer includes2. **Inference:** fallback took Ruby key. This inference is stronger than a generic no-op guess, but the OOC trace does not serialize keys or the precise fallback action. A public exact-action receipt or source replay would close that gap.

This makes an opt-in deterministic campfire fallback a distinct minimal hypothesis from RestOff. RestOff only removes the V4 gate and can expose more random actions. A fair comparison should retain V4 first and change only fallback, or explicitly test a replacement rule as another arm. Excluding unnecessary key actions is a separate factor unless the combined safety rule is preregistered as one intervention.

For the same source, f2 Mango is genuinely V4-owned: `Fprod_2.strategic.jsonl:185`, margin7.940765, selected relic index0. The f11 removal is V4-declined (row195 margin0.009888). Attribution matters: one is learned action ranking; the other is fallback shop/removal behavior. No single architecture explanation accounts for both without further tests.

## Audit limitations and next discrimination

- The scripted summary preserves every chronology row and source locator. It does not prove exact fallback action identity. Relic counters, keys, deck positions, and intra-combat potion order are absent; unchanged inventory can conceal RECALL/LIFT.
- All twelve tree profiles contain gameplay records and zero serialized root errors in the reviewed summary. The concrete useless-action classifier reports no positive proof in this cohort, within its narrow last-Defend/no-potion class. That does not establish optimal combat play or universal action usefulness.
- Q margins are model score gaps, not calibrated uncertainty or expected win-probability gains. Native root profiles report search effort and selected action but not a complete reliable action-value uncertainty interval.
- The clean full-health REST examples, random fallback example, removal examples, and positive interaction controls justify narrow experiments. They do not identify a champion. Whole-run paired comparisons and the untouched reserved confirmation cohort remain decisive.
- Public-only alternative review for source610081015 was delegated independently to strategy before any continuation results; its outcome is not included here.
