# GEN2 profiler identity repair

The first contract check failed before numerical outcome reporting because the verifier assumed every combat tree row carries the original source seed. This assumption contradicts the frozen producer's intended hidden-future redraw. It is a verifier provenance mismatch, not evidence of a runtime search failure.

`apps/one_combat/combat_datasets.cpp` creates each GEN2 future seed from the first sixteen hexadecimal digits of SHA256 over `ooc-cf-pilot-v2-future:{sourceSeed}:{decisionIdx}:{k}`. Before forcing the action, `runCombatEvalGenSeed` constructs `std::mt19937_64` with that future seed and calls `resampleCounterfactualFuture`. In `apps/one_combat/ooc_mcts_adapter.cpp`, `sampleNoncombatFuture` immediately assigns `gc.seed = rng()`. The tree profiler in `src/sim/search/NativeSilverBackend.cpp` serializes this `gc.seed`. Source roots therefore use the original source seed; continuation roots use the first mt19937_64 output for the declared decision/future pair.

The diagnostic inspected only options identity fields and tree provenance/budget/error fields. No numerical label rows were opened. Across 38,267 profile rows from four sources, every seed matched the exact producer-derived set; there were zero unexpected seeds, zero adaptive rows, zero error rows, and zero negative-budget rows. All expected source/future seed classes were present in this observed cohort. The full mapping and immutable raw hashes are in `gen2_profile_seed_diagnosis.json`.

The narrow correction derives the allowed set from the hash-verified options decision indices and frozen future allocation, never from observed profile seeds or outcome labels. It retains rejection of unrelated seeds, adaptive search, runtime errors, and negative budgets, and additionally requires an original-source profile row. It does not claim each sibling branch has an individually attributed profile: the profiler lacks a branch-id tag, and several siblings share a future seed.

The original invalid `gen2_canary_3ed9/contract_receipt.json` and old `verify_gen2_v1.py` remain unchanged. After independent review, a new uniquely named receipt may validate the same immutable raw data under the corrected provenance invariant. This correction authorizes no game rerun, numerical action selection, training, or strength claim.

`test_gen2_profile_seeds.py` checks four first-output vectors independently obtained from system libstdc++ using the arithmetic-only `mt19937_64_vectors.cpp`, the exact source/future seed domain, and rejection of unknown seed/adaptive/error/negative-budget fixtures. All five tests pass. A first fixture used the expected seed set for decision 71 while naming decision 36; that test-only mismatch and its correction are preserved in `gen2_profile_seed_fix_checks.json`.
