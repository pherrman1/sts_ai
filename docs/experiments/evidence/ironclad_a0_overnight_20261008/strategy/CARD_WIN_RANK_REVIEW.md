## Concept and isolation

The treatment changes one conceptual variable: the ranking among offered cards at native fallback reward roots where the existing floor model elects to take a card. The same floor model, feature edits, public8 scenarios, configured floor skip threshold and first-strict-maximum tie rule make the take/skip decision. If that decision skips, the helper returns sentinel5 without evaluating the win head. If it takes, the loaded logistic win head ranks cards without a win-based skip threshold. No new model, threshold tuning, V4 scoring, legality rule or card-acquisition mechanic is introduced.

Take/skip preservation applies to an identical reached reward state. A changed acquisition alters later states, so total trajectory skip counts, later V4 ownership and downstream outcomes need not match. Multiple reward groups can also diverge after the first changed card. This is ordinary downstream treatment effect, not evidence that the per-root contract failed.

Historical broad win-head testing was inconclusive (the recorded512-run comparison did not improve the floor baseline), and this narrower hypothesis must retain that contrary evidence. The corrected first12 source-order audit shows native fallback exposure at190 of306 card decisions; that supports a non-inert screen, not an expected gain. Acquisition feature edits remain approximate: card IDs and deck size change, while upgrade differences, Eggs/on-acquisition effects and contextual synergy are not newly modeled. A win-trained head can still be miscalibrated on these hypothetical rows.

## Helper source findings

The strict `STS_OOC_CARD_WIN_RANK` getter accepts unset/0 as false and1 as true; malformed values throw. The disabled helper immediately delegates to the existing floor helper, ignores an unavailable optional win model and leaves the optional new trace untouched. Enabled mode requires public count8, loaded floor and win models, a logistic win model, a REWARDS screen, a valid reward-group index and a finite floor threshold.

The floor-ranking loop duplicates the existing calculation exactly for supported finite predictions: one unchanged public base row, +1 card-ID count and +1 deck size for each card, subtract baseline prediction, first strict maximum, and the same strict-below threshold skip rule. It returns skip before constructing a win scorer. Enabled taken roots perform the same feature edits for the win model and choose its strict argmax without a skip comparison.

Both model scorers are constructed from the identical unchanged GameContext and PathHistory. The sampler seed is independent of the model and excludes true seed, private RNG and hidden encounter suffixes. Therefore both heads and every candidate use the same eight scenarios. Each scorer averages model predictions after the link function; the logistic head computes a probability mixture rather than taking a sigmoid of a mean margin. Scoring does not execute a candidate or mutate source state/RNG. The existing diagnostic public-scorer counter increases once for a skipped root and twice for a taken root; this is inference accounting, not gameplay state.

PublicValueScorer rejects nonfinite returned predictions. The helper additionally rejects a nonfinite averaged base value and nonfinite marginals. This catches aggregate overflow even on an empty reward group where no marginal is evaluated. Model loading already rejects nonfinite parameters, malformed indices and cycles. The generic logistic predictor itself clamps a NaN accumulated margin to1 because of its std::min/std::max ordering; this inherited behavior means arbitrary post-load in-memory NaN mutation is not a valid fixture for returned-NaN handling. The helper does not claim to revalidate every loaded model node at each root or repair the generic predictor. An explicit cycle produces its documented early NaN return and can test this wrapper boundary without broadening the change.

Trace collection records predictions already made: floor baseline/marginals, baseline choice, win-evaluated marker, optional win baseline/marginals, final choice and scenario count. It adds no model calls and is not action execution. Disabled trace data is intentionally untouched. Startup banners alone will not prove the changed ranker was reached or changed an action; a guarded runtime canary must establish equal public prefix and a concrete floor-versus-win ranking when exposed.

## Fixture and integration gates

During independent inspection, the original win-NaN fixture used NaN base/leaf values that the inherited logistic clamp converted to1. This would fail the intended rejection assertion without indicating a helper-policy defect. The finding was returned to the author before compilation; correction should use the predictor's explicit cycle-NaN path and preserve loader provenance boundaries. Non-logistic floor NaN fixtures are valid. Additional focused checks requested: invalid screen/index/threshold guards and a negative-marginal win head that still must take when the floor chooses take.

Existing inspected fixture structure covers default delegation under public0/8 with an unavailable win head, prediction-count parity, unchanged diagnostic trace when disabled, actual card reranking, floor skip preservation with no win inference, strict ties/equal-threshold behavior, analytical post-link mixture equality, all fourteen source RNG objects/seed plus hidden-suffix perturbation, and source fingerprint purity. The analytical mixture varies a hidden encounter split and uses an independent probability formula, so it can distinguish shared scenarios/post-link averaging from superficially matching actions.

Application integration must restrict this helper to the native card-reward fallback. The namespaced baseline helper remains the live-advisor/MCTS implementation. Regret gating calls the fallback to identify its reference action, so an enabled ranker must reject regret mode to uphold the unchanged V4-gate claim. The global baseline wrapper also has an act-fight-probe diagnostic caller; fallback-scope dispatch and incompatible-mode startup guards prevent changing that independent lane. Alternate legacy CARD_WIN/CARD_NN/CARD_ACTION, boss blends, MCTS and other unsupported policy variants require explicit rejection rather than silently bypassing this treatment. Conditional teacher policy metadata must bind the new flag while leaving unset/0 specifications unchanged.

Mutex/JSON output can change timing but introduces no game/agent RNG use or model call. The trace is sufficient to show the actual local rank delta when joined to the frozen run identity and chronological OOC trace; it is not a self-contained full state snapshot, and duplicated semantic cards remain disambiguated by their indices.

Teacher serialization adds only `flags.native_ooc_card_win_rank=true` when enabled, preserving the previous policy JSON when unset/0.
