## Verified controls and useful seams

The requested Bprod/Bflat strategic profile loads the token model, enables REST/EVENT/SHOP/TREASURE/BOSS_RELIC gates, sets global margin 1, uses native floor-V fallback card/shop decisions, and disables native win-based rest. `bestbench` forces `shopV=true`. Combat differs only as specified by the charter. Relevant source: `apps/one_combat/run_driver.cpp:278`, `apps/one_combat/ooc_policy.cpp:224`, and baseline `arm_env.sh`.

- `STS_OOC_STRATEGIC_CARD` appears in provenance output but is **not parsed**. Card scoring activates whenever the token model loads. A finite large `STS_OOC_STRATEGIC_MARGIN_CARD` is an existing practical bypass; true disabling deserves a tiny explicit flag if wanted. Preserve singleton behavior if changing the API.
- Token Q is an unbounded raw head, trained by default on `10*labelWon+labelHp`, not a probability or pure floor scale (`train_strategic_tok.py:233`; `apps/ooc_strategic_tok_net.h:519`). `STS_OOC_STRATEGIC_Q` and `STS_OOC_STRATEGIC_SCORE` affect the older rich-state net, **not** V4 token scoring.
- `STS_OOC_STRATEGIC_REST=0` disables both REST and UPGRADE-target token gates. Its fallback with `STS_REST_WIN=0` is ScumSearchAgent2's rule/random campfire policy and expert upgrade order (`src/sim/search/ScumSearchAgent2.cpp:165`). It does not mean always upgrade.
- `STS_OOC_STRATEGIC_BOSS_RELIC=0`, with `STS_BOSS_RELIC=0`, uses fixed `Expert::getBossRelicOrdering` (`ScumSearchAgent2.cpp:150`). With BOSS_RELIC enabled it instead evaluates actual successors through win value, including randomness; that is a different treatment and must not be silently bundled.
- `STS_OOC_STRATEGIC_SHOP=0` delegates to `nativeShopPlan`. `STS_SHOP_WIN=1` disables the native floor fast path and routes to the server; hold it at zero. Likewise treasure ablation has limited exposure after the already-landed chest rule and must not be presented as a new chest fix.
- `STS_SKIP_THR=0` changes fallback card acceptance from the baseline -0.5 while preserving the V4 card gate. Raising the threshold above zero has historical starvation risk; do not launch a Cartesian sweep.
- `STS_OOC_STRATEGIC_TRACE=<csv>` is existing candidate-Q/gate instrumentation; `STS_OOC_DECISION_TRACE` gives chronological public state and action deltas. The first selects the slower general card scorer instead of its shared fast path, so on/off neutrality needs checking before combining traced and untraced results.

## Direct simulation contract and limitations

Prefer `ooccfpilotgen ... FUTURES STATES_PER_SEED CARD_BOSSES 2 BOSS_RELIC` for the initial direct-rollout test, subject to the coordinator's frozen teacher/protocol. GEN2 uses real native Silver under the configured teacher budget (flat exact10k or explicitly accepted learned stopping), forces each retained semantic action, resamples hidden futures before the option, fail-closes when published screen/public rich fields change, and records absolute `finalWon`. First postdecision MAP features vary legitimately after boss relics. Preserve future sample identity and source grouping.

Selection and independent evaluation can use disjoint k subsets from a fixed GEN2 tranche, if declared before labels are inspected. The original frozen wave code had no `futureStart` argument; the separately reviewed targeted-GEN2 extension adds it. On the original producer, rerunning with a larger FUTURES repeats the earlier k range. Do not treat rerun k=0 as fresh confirmation. The teacher requires the recorded production OOC profile; source and branch both honor the configured native budget. A mismatched campaign profile requires an explicit provenance-compatible teacher, not relabeling historical outputs. A source snapshot/replay extension can be worthwhile if repeated source regeneration becomes costly, but that is a bounded change for the coordinator to assign.

`STS_ACT_FIGHT_PROBE_ALL_OOC` is not an off-the-shelf implementation of the charter's rollout challenger. It controls all screens, scores checkpoint utility, uses `resampleRemainingActEncounters`, and has separate policy machinery (`one_combat.cpp:2272`). Simply turning it on would introduce several conceptual differences. Reuse GEN2 and its full-run/redraw contract for a restricted selector.

The prior diagnostics are decisive constraints on repetition: #429 / ledger sections 389-390 found full-HP rests, chest skipping and relic skipping in selected MCTS/fallback trajectories; #431 already fixed the chest/reward/key rules. Section 392's uniform-prior gain was limited to selected source entries and two of four unchanged seeds. Section 393's one-arm uniform+rules pilot was 18/32. Section 391 / #430's bossrollout leaf was 9/32 and approximately 1297 s/game, with noisy next-boss survival and CTM approximations. This does not reject real Act-3 one-step rollout, but it rules out describing uniform prior or boss-survival rollout as newly demonstrated solutions.
