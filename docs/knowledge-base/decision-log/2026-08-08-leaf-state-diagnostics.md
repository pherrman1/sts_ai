# 2026-08-08 — Leaf-state diagnostics: measure the §126-vs-§134 online gap on actual Searcher3 leaf states

Date: 2026-08-08
Session/task: Handover "explain why the deployed end-HP V-net helps Searcher3
while better terminal-value models fail online" — build diagnostics that
measure how the deployed end-HP vnet and the direct utility-R vnet behave on
actual Searcher3 leaf/candidate states (EXPERIMENTS.md §126 vs §134).

## Decision

Do NOT train another absolute terminal-return regressor this cycle. Instead,
build the measurement infrastructure first:

1. `search::g_onS3LeafQuery` / `S3LeafDiagnostic` (thread_local, nullptr by
   default) fire inside `BattleScumSearcher3::step` at the leaf-expansion
   blend site — the exact states the learned leaf scores.
2. `one_combat leafdiag` records a per-stratum reservoir of those states with
   canonical combat features, both model predictions (deployed end-HP vnet +
   `STS_DIAG_VNET2` secondary, never read by the search), raw/blended rollout
   evals, and full provenance; sampling is deterministic per seed.
3. `one_combat leafref` replays the recorded decisions and writes
   CRN-paired high-budget Searcher3 reference values (documented as
   `referenceValue` — an approximation, never ground truth).
4. `one_combat rollouttrace` + `search::g_onRolloutStep` write actual
   search-policy rollout state sequences for delta-V smoothness analysis.
5. Analysis scripts: `tools/leaf_ranking.py` (within-group pairwise ranking /
   top-1 / regret / stratified), `tools/leaf_distribution_shift.py`
   (combatgen-vs-search-leaf covariate shift, ROC-AUC, `--write-ood`),
   `tools/leaf_split_check.py` (fight-level vs seed-level split sensitivity),
   `tools/leaf_smoothness.py` (delta-V shaping).

Defaults are preserved byte-identically: the hooks are nullptr-checked before
any work and the leaf obsHash is computed only inside the guard; the
`leafdiag`/`leafref`/`rollouttrace` modes force `STS_FAIR=1 STS_SEARCHER3=1`
and are off unless invoked.

## Rationale

- The §126 end-HP leaf is +12.1pp online over the §134 direct-R leaf, yet the
  direct-R model fits its target far better offline (val MAE 9.73 vs 45.82 —
  the latter partly a scale artifact; EXPERIMENTS.md §134). Offline regression
  error on on-policy trajectory states cannot distinguish the candidate
  hypotheses (train/search distribution shift, ranking-vs-absolute-value,
  end-HP as a shaping/potential function). The cheapest separating evidence is
  to measure both models ON the states the search actually scores.
- **Inference** — the leaf-state identity should be the leaf state's own
  `visibleHash`, not `cur->obsHash`: at the blend site `cur` is the expanded
  PARENT (its observation predates the committed action + chain compression),
  so the plan's `cur->obsHash` would mis-key the leaves. Verified: leafref
  replay regenerates the identical leaves (450/450 obsHash matches on the
  smoke), which confirms the hash + replay determinism together.
- **Inference** — CRN pairing across sibling leaves is done by reseeding each
  reference searcher's rng + belief + particles from one per-group seed rather
  than toggling the global `g_s3Crn` warm-start (a global toggle would race
  across threads and change other threads' replay searches).
- The `leafdiag`/`leafref`/`rollouttrace` runs must NOT enable the probing OOC
  arms (STS_OOC_ACTION_NN, STS_BOSS_DRAFT, M1/M2 path gates, STS_DATAGEN_GATES,
  …) — their inner probe battles fire the leaf hook and pollute the dataset.

## Alternatives considered

- Train a ranking/advantage model on sibling states directly — rejected for
  this cycle: the task explicitly says "do not start with another model";
  diagnostics first.
- Reconstruct trajectory states from seed history instead of a trace mode —
  rejected: the plan's Task 6 invariant requires ACTUAL search rollouts, so a
  `rollouttrace` mode with the in-searcher `g_onRolloutStep` hook was built
  (reconstruction risks rollout-policy drift).
- A leafref "replay to decision and capture root only" design — rejected: the
  reference must be per-LEAF (for within-group pairwise ranking), so leaves
  are regenerated by re-running the deterministic search and matched by
  obsHash.

## Corrections (review pass, 2026-08-08)

- The leafdiag CSV provenance stores the encounter as its UPPER_CASE enum NAME
  (`encounterName` column, `monsterEncounterEnumNames[(int)bc.encounter]`);
  the numeric `encounter`/`turn` encodings live in the canonical feature block
  only — there are no duplicate `encounter`/`turn` columns (Python
  `csv.DictReader` would shadow the name with the feature-vector value).
- The leafref CRN pairing is PARTIAL: reseeding rng+belief+particles from one
  per-group seed shares only the determinization PREFIX — `Belief::initial`
  and `prepareCRNParticles` each shuffle the draw pile, consuming a
  state-dependent number of draws, so sibling streams diverge afterwards.
- The reference values are NOT model-free: the high-budget reference Searcher3
  runs with the same deployed `STS_VNET` @ configured alpha as the leafdiag
  run. Sensitivity checks before the verdict: rank vs `rawRolloutEval`, or a
  leafref run with `STS_VNET` pointed at a missing path (load fails, vnet
  stays off).
- leafref/rollouttrace replay must match the leafdiag run config (particles,
  `STS_VNET`+alpha, OOC env arms, ascension); both modes now print a
  re-capture WARNING when re-captured < recorded leaves.

## Results addendum (same day)

Gate-matching 64-seed measurement (seeds 126700–126763, α0.3, per-stratum 500,
full V4 OOC arms, local 12 threads) recorded in EXPERIMENTS.md §135a:

- **Distribution shift is massive:** held-out logistic combatgen-vs-search-leaf
  ROC-AUC 0.9998; essentially all search-leaf groups are OOD vs
  `vcombat_honest.csv`. Hypothesis 1 is strongly supported.
- **endHp ranks slightly better on actual search leaves** despite fitting the
  high-budget reference worse: pairwise 0.719 vs 0.711, top-1 0.359 vs 0.336,
  regret 7.25 vs 7.60; Spearman 0.769 vs 0.820. Direction confirmed model-free
  (rawRolloutEval reference). Hypothesis 2 supported but the effect is small.
- **Shaping mixed:** endHp smoother (lag1AC 0.549 vs 0.502, near-death
  std 3.2 vs 8.6) but utilityR more sign-consistent on surface progress.
  Hypothesis 3 inconclusive.
- **Split check:** fight-level validation is not optimistic (seed-level
  slightly easier). Task 5 answered: offline metrics were not leakage-inflated.
- **Next experiment (covariate-shift branch):** mixture retrain (combatgen +
  leafdiag states) with separate on-policy and search-leaf holdouts; test
  search-leaf ranking before any gate. No promotion, deployed §126 vnet
  unchanged.
