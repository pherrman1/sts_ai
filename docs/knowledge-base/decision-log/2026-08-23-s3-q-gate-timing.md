# 2026-08-23 — Searcher3 Q-gate timing result

## Decision

Stop the Always-Q line. The corrected timing diagnostic found that the
baseline Searcher3 Q gate opened by simulation 10 in 3,446 of 3,449 searches
(99.91%), so the planned late/no-win paired experiment was not run. This is a
timing result only: it makes no gameplay win-rate or equal-CPU claim.

## Exact semantics

`firstQExploitSimulation` is a per-`BattleScumSearcher3` field initialized to
`-1`. It records the first one-based simulation ordinal after backpropagation
changes `bestActionSequence` from empty to non-empty. That is the existing
baseline exploit-gate condition. It is not terminal-win timing, and the
telemetry does not alter selection, rollout, rewards, model evaluation, or
random-number consumption.

The opt-in `STS_S3_GATE_TIMING_DIAG` writes one row after each real Searcher3
combat search. `tools/analyze_s3_q_gate_timing.py` validates exact captured
state/search identity and reports the preregistered bins.
