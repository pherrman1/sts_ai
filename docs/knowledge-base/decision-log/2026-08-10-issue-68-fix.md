# 2026-08-10 — issue 68 fixed (stale multi-select validation outside CARD_SELECT)

Date: 2026-08-10
Session/task: Investigator-audit bug-fix pass, `src/sim/search/Action.cpp`

## Decision

- `isValidMultiCardSelectAction` now returns `false` unless
  `bc.inputState == InputState::CARD_SELECT`, the same gate
  `isValidSingleCardSelectAction` already had. `cardSelectInfo.cardSelectTask`
  is only meaningful while a card select is open; after the select resolves,
  `Action::execute` moves the state through `EXECUTING_ACTIONS` back to
  `PLAYER_NORMAL` and the task field is stale. Before the fix, an
  EXHAUST_MANY/GAMBLE mask could validate against the stale task in a
  `PLAYER_NORMAL` state, which is reachable via the fair-mode edge re-check in
  `BattleScumSearcher2` (a stored edge from another determinization is
  re-validated against the current world's state).
- The GAMBLE/EXHAUST_MANY mask bits themselves are part of the action, not the
  state; the execute helpers are only ever reached through validated actions,
  so no change was needed on the execution side.

## Rationale

- Consistency: the single-select sibling already refuses validation outside
  `CARD_SELECT`; multi-select should not be more permissive.
- **Inference:** the guard only rejects actions that could not have been
  enumerated in a `CARD_SELECT` state and could not have arisen from a
  completed select; it cannot prune any legal in-state selection.

## Alternatives considered

- Clearing `cardSelectInfo.cardSelectTask` when the select resolves — rejected
  as a larger behavioral change: the task field is also read by debug printing
  and by the parity tests, and the guard at the validation boundary is the
  minimal contract fix (the same approach the single-select path already uses).

## Evidence

- `src/sim/search/Action.cpp::isValidMultiCardSelectAction` (new input-state
  guard; single-select guard pre-existing at `isValidSingleCardSelectAction`).
- `src/sim/search/BattleScumSearcher2.cpp` fair-mode edge re-validation
  (`g_fairPlay && !edgeTaken.action.isValidAction(curState)`).
- Regression tests added to `apps/test.cpp::testIssueFixes` (`issue_fixes`
  ctest): EXHAUST_MANY and GAMBLE masks validate in `CARD_SELECT` and are
  rejected with the same stale task once `inputState == PLAYER_NORMAL`.
- `cardselect_parity` and `cardselect_canonical` still pass (fixtures are in
  `CARD_SELECT` state, so the guard is a no-op for them).
- `ctest --test-dir build --output-on-failure`: 22/22 pass.

## Status and follow-up

- Issue 68 marked fixed in `docs/knowledge-base/issues/`.
- No follow-up: the guard completes the validation contract; the stale-task
  field remains as a documented limitation of the state representation.
