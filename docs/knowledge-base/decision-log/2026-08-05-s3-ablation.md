# 2026-08-05 — S3 feature ablation at 3k: belief, chain, CRN net-negative; prune/live inert

**Date:** 2026-08-05. **Task:** attribute Searcher3's same-cost +5.5pp
signal (payoff gate §102, default OOC stack) to its individual mechanisms at
the operating point (V4 gate stack, fair, A0, 3k sims). Benchmarked in
`EXPERIMENTS.md` §106.

## Decisions

1. **The S3 package's gain lives in its determinization core, not its
   extras.** Removing the particle belief reweighting (A2) and the chain
   compression (A4) both *improve* win rate (+8.6pp / +4.7pp vs the S3
   control); removing the pruning (A3) or the live-valid root filter (A5)
   changes nothing (per-seed bit-identical on all 128 seeds); enabling the
   root CRN warm start (A6) *loses* −14.1pp (CI excludes 0). A2 is the only
   arm that beats the S2 reference with CI excluding zero (+14.1
   [+3.5,+24.7]).
2. **The `STS_S3_*` ablation flags stay opt-in; no default change yet.**
   A2's CI versus the S3 control touches 0 at n=128; the combined
   S3−belief−chain arm on 256 seeds must confirm before any default
   recommendation change.
3. **CRN was shipped dead and stays off.** `warmStartRootCRN`/
   `prepareCRNParticles` were never called; `crnTiebreak` is declared and
   never defined. Now reachable only via `STS_S3_CRN=1`, which is harmful
   anyway — the dead-code status was load-bearing, not a bug.
4. **Process:** benchmark on GCP `sts-test` via `gcloud compute ssh` (the
   `sts-test` ssh alias alone does not resolve; gcloud identity works). The
   per-seed row order of `bestbench` CSVs is completion order, not seed
   order — pair on the `seed` key, never on row position.

## Rationale

- With 64 particles, reweighting concentrates the belief on the few
  hypotheses matching the early draws; uniform resampling preserves
  diversity, and the exploration win shows up in A2's +8.6pp
  (**Inference**).
- Chain compression commits the rollout to a card-spam line before search
  weighs alternatives; A4 removes it and wins +4.7pp (**Inference**).
- A3/A5 bit-identical to ctl is *evidence*, not noise: `canPruneAsDead`
  never changes an outcome and the fair live-valid filter never changes the
  selected root edge (fresh tree per decision, edges enumerated from the
  live battle).
- CRN's −14.1pp: 64 fixed rollouts per root edge inject a noisy Q prior
  PUCT trusts (**Inference**).
- All labelled per the contract; the A2-vs-S2 and A6-vs-ctl CIs are
  significant, the A2-vs-ctl and A4-vs-ctl CIs are within noise at n=128.

## Alternatives considered

- **Run the ablation on the default stack** (as the §102 gate did) —
  rejected: the operating point is the V4 gate stack; A0 verifies it
  bit-identically against the recorded §99 128-slice (0 non-`sec` diffs).
- **Ablate by re-enabling features on a stripped S3** — rejected: the
  removal (leave-one-out) design isolates each feature's marginal
  contribution on the deployed package.
- **Combined-arm first** (S3−belief−chain) — rejected for the screening
  wave: it cannot attribute; the leave-one-out matrix comes first. The
  combined arm is the stated follow-up.
