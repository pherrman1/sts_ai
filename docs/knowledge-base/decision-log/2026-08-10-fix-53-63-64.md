# 2026-08-10 — Fix issues 53, 63, 64 (fairy+bark revive HP, Peace Pipe TOKE no-op, CF branch RNG pollution)

Date: 2026-08-10
Session/task: Implement fixes for issues #53, #63, #64 from
`docs/knowledge-base/issues/`.

## Decision

Apply the three bug fixes in `src/game/GameContext.cpp` and add regression
tests to `apps/test.cpp` `testIssueFixes()`.

- **#53** `GameContext::playerOnDie`: parenthesize the Sacred Bark ternary so
  `hasBark ? 0.6f : 0.3f` is multiplied by max HP. Previously `*` bound tighter
  than `?:`, so a Bark revive cast `0.6f` to `0` and revived at `max(1,0)=1`.
- **#63** `GameContext::chooseCampfireOption` case 4 (TOKE): remove the eager
  `regainControl()` that closed the remove card-select screen before any pick;
  the pick path `chooseSelectCardScreenOption` (REMOVE) already calls
  `regainControl()` itself, matching the SMITH case.
- **#64** event-fight `regainControlAction` lambdas in `chooseEventOption`:
  qualify member calls with the `gc` argument instead of the `[=]`-captured
  `this` (DEAD_ADVENTURER, DESIGNER_IN_SPIRE case 4, MINDBLOOM case 0,
  HYPNOTIZING_COLORED_MUSHROOMS). A branch copy inherits the pending lambda,
  so the captured `this` is the original context; consuming RNG on `this`
  advanced the live run's streams and broke the CRN invariant.

## Rationale

- `regainControlAction` is always invoked with the owning context
  (`regainControl()` → `regainControlAction(*this)`; `BattleContext::exitBattle`
  → `g.regainControl()`), so `gc` is the correct object to mutate/consume RNG
  from in every call pattern, live or branch. In the live run `this == gc`, so
  behavior is unchanged there.
- The lambdas at MASKED_BANDITS (already `[goldAmt]` + `gc.createCardReward`)
  and MYSTERIOUS_SPHERE (only `gc.afterBattle()`) need no change. The issue's
  "MASKED_BANDITS ~line 3030" attribution actually points at the MINDBLOOM
  lambda, which had the same `addPotionRewards` on `this` bug and was fixed.

## Alternatives considered

- Capture a `shared_ptr<GameContext>` in the lambda — rejected: the lambdas are
  stored inside the context itself and there is no owner besides the run; the
  `gc` argument is already the correct object.
- Leaving a FIXME comment only — rejected: the fix is a local, verifiable
  one-line-per-site qualification.
