# 2026-08-10 — issue 82 fixed (native-OOC gate batches no longer start v_server)

Date: 2026-08-10
Session/task: Investigator-audit fix pass, `selfplay/loop.sh`

## Decision

- Added `selfplay/loop.sh::needs_server`, which returns true iff the current
  gate env (`MEAS_POLICY_ENV`) carries `STS_NATIVE_OOC=0` (exact token match).
- The `start_server` call in every native-OOC gate batch is now guarded:
  baseline cache growth (`ensure_baseline_cache`), the value gate, and the
  policy gate. Each call site became
  `{ needs_server && ! start_server ...; } || ! run_gate_batch ...`, so the
  server is started only when the batch is server-backed, and a server failure
  still fails a server-backed batch exactly as before (Issue 01 semantics).
- The meta gate keeps its unconditional `start_server` (Issue 01): its env is
  always `META_POLICY_ENV` with `STS_NATIVE_OOC=0`, so the candidate V_win/rest
  must be served by v_server and a missing server must fail the batch.

## Rationale

- Value/policy gate batches run `bestbench` with `MEAS_POLICY_ENV=$POLICY_ENV`
  (native OOC, `STS_NATIVE_OOC=1` default), so they never consult v_server; a
  server failure (or an absent server) failed them needlessly. The baseline
  cache gate is also native-OOC (its cache key comment already called out
  "Native-OOC gates (baseline/value/policy)"), so it is guarded too — otherwise
  a server failure during a cache miss would still fail the value/policy arms.
- The guard is keyed on the env rather than hard-deleting the calls so a future
  change that makes an arm server-backed gets the server automatically.

## Alternatives considered

- Removing the `start_server` calls outright from the native gate blocks —
  rejected: brittle if an arm's env later becomes server-backed, and it would
  have silently dropped the server for the baseline cache path as well.
- Guarding only the value and policy gate sites (the literal issue text) —
  rejected: the shared baseline-cache `start_server` is equally native-OOC and
  runs before every gate look, so a cache miss with a dead server would still
  fail the native arms.

## Evidence

- `selfplay/loop.sh::needs_server` (added), guarded call sites in
  `ensure_baseline_cache`, value gate block, policy gate block; meta gate block
  unchanged.
- `bash -n selfplay/loop.sh` passes; a standalone harness verified: native env
  skips `start_server` and runs the batch, server-backed env starts the server,
  server-backed + server failure takes the error branch, native env + batch
  failure takes the error branch, and `STS_NATIVE_OOC=00` does not match.

## Status and follow-up

Closed. Doc updated: `docs/knowledge-base/operations/selfplay-loop.md`
(native-OOC gate batches skip `start_server`; server required only by the meta
arm), issue entry `2026-08-10-issue-82-loop-gate-server-dependency.md` marked
closed, issues index row added. No behavioral change to native gate results
(server was started but never consulted).
