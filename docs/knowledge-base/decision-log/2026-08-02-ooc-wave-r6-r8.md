## Decisions

1. **R6 — one-ply Q gates for shop / TREASURE / boss relic are deployed-able
   and statistically established.** Three new gate functions
   (`oocOnePlyShopPolicy`, `oocOnePlyTreasurePolicy`, `oocOnePlyBossRelicPolicy`,
   apps/one_combat.cpp) behind `STS_OOC_STRATEGIC_{SHOP,TREASURE,BOSS_RELIC}=1`
   (default off). Paired 128-seed fair benchmark (1,000 sims, baseline
   `build/tierb_gate_base.csv` 21.1%): full stack at margins 0.5/1.0 =
   **39.8% wins (+18.8pp, win CI [+9.4,+28.1]pp, floor CI [+1.1,+6.0])** — the
   first statistically established Phase-5 result; margin 5.0 neutral (gates
   barely fire). Shop-only ablation +3.1pp, so treasure + boss relic carry the
   bulk (boss relic choice is the highest-value gated decision; the heuristic
   `bossRelicVPolicy` was comparatively weak).
2. **R7 — the Q head is NOT the V4 calibration bottleneck.** V3-state +
   V4-entity Q head A/B (`train_strategic_qiso.py`, entity on/off): Q MAE
   14.47/14.43 ≈ V3's 14.32, vs V4's 16.2 — the token state encoder caused
   V4's calibration gap. Entity conditioning on the V3 state: neutral for Q,
   mildly positive for policy ranking (top-1 0.790 vs 0.782, val CE 0.491 vs
   0.516). Implication: keep the V3 state for deployed Q; token-state revival
   must come from Phase B encoders or Phase C probes.
3. **K=1 label horizon beats K=3 on Q calibration.** V3 CE+Q trained on
   `build/strategic_k1.csv` (649,968 rows / 1,000 seeds, K=1 branch):
   Q MAE 7.50 / Q top-1 0.306 vs the §73 K=3 model's 14.32 / 0.284 (value MAE
   2.83 vs 5.45); policy top-1 slightly worse (0.771 vs 0.784). Hypothesis:
   K=1 targets compound less bootstrap noise (shorter horizon, less variance).
   Direct test queued: the K=1 Q head through the full gate stack.
4. **seed-128087 isolation** (src/combat/BattleContext.cpp loop guard): the
   recorded crash was a non-terminating card-generation runaway (int16
   uniqueId wrap at 32769); in Release builds the `assert` was a no-op so the
   guard printed a state dump every iteration (the recorded "crash dump"
   hang). Fix: compact `[loop-guard]` warning + `outcome = PLAYER_LOSS; break`
   (same semantics as the existing turn>500 branch). Seed 128087 now completes
   (402 rows @ 200 sims); neighbours + determinism spot-check verified.
5. **Phase C approach confirmed** (inventory): extend the no-peek entry model
   into C_ψ using existing distgen labels (`build/vdist.csv`, 2,828,241 rows,
   has endTurn/potionsConsumed/pUsed0-43) — no new datagen needed. New trainer
   `train_combat_cpsi.py` (no-peek structural inputs, death/win/HP-quantile/
   potion/turns heads, `combat_cpsi_v1` export); training queued.

## Rationale

- **Inference:** the gate stack's jump from +7.0pp (§74) to +18.8pp when the
  remaining screens are covered suggests the Q head's value concentrates in
  screens where the heuristic was weakest; the marginal screens were the
  remaining unlocked value.
- **Inference:** R7's identical Q MAE across entity on/off isolates the state
  encoder as the V4 gap driver; the token encoder's extra capacity did not
  transfer to Q calibration on this label contract.
- **Inference:** K=1's lower Q MAE is consistent with variance reduction
  (1 fight + bootstrap vs 3 fights + bootstrap) dominating horizon
  information; the gate benchmark decides whether ranking transfer follows.
- **Verified:** R6 determinism (rerun bit-identical excl. `sec`); R7 held-out
  metrics; K=1 datagen determinism; seed fix reproductions.

## Alternatives considered

- R6: gating treasure with a static "always open" policy — rejected: the Q
  gate benchmark is the decision metric and it wins.
- R7: exporting the Q-iso net for a gate round immediately — deferred until
  the R8/K1 results settle the Q-head contract; the held-out evidence was the
  cheap decision.
- K=1: using more seeds instead of fewer battles — rejected for this test:
  the A/B controls the label horizon, not data volume.
- Seed fix: deeper root-cause of the runaway fight — not found within budget;
  the isolation matches the existing turn>500 precedent and cannot mask a
  healthy-fight bug.
