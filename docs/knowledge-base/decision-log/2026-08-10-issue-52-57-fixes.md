# 2026-08-10 — issues 52, 57 fixed (empty action stubs crash, Time Eater exhaust flag)

Date: 2026-08-10
Session/task: Investigator-audit bug-fix pass on `src/combat/Actions.cpp`

## Decision

- **Issue 52 (empty `actFunc` crash):** the four action factories that returned
  `sts::Action()` (empty `actFunc`, invoked unconditionally by
  `BattleContext::executeActions` → `std::bad_function_call` →
  `std::terminate`) now all return actions with a valid `actFunc`:
  - `PoisonLoseHpAction` gained a `monsterIdx` parameter (declaration in
    `include/combat/Actions.h`, call site `Monster.cpp::applyStartOfTurnPowers`
    passes `this->idx`, restoring the per-monster targeting the Java game has).
    Body: skip if the monster is dead/escaped or unpoisoned, deal the poison
    amount as **unblockable** damage via `Monster::damageUnblockedHelper`
    (matching the original game's `DamageType.THORNS`), then decrement poison
    by 1, then `bc.checkCombat()`.
  - `ChangeStance`, `EssenceOfDarkness`, `IncreaseOrbSlots` are explicit no-op
    lambdas (stance/orb systems not implemented); they no longer crash.
- **Issue 57 (Time Eater exhaust flag on wrong card):**
  `TimeEaterPlayCardQueueItem` now ORs the *replayed* card's own exhaust
  property (`item.card.doesExhaust()`) instead of the triggering card's
  (`bc.curCardQueueItem.card.doesExhaust()`), so a replayed Fiend Fire exhausts
  correctly.

## Rationale

- #52: the actions are queued today only in unreachable paths (poison sources
  are Silent-only; stances/orbs are unwired in Ironclad), but the audit showed
  the unconditional `actFunc()` invocation in `executeActions` turns any future
  class/pool expansion into an instant `terminate()`. Filling the stubs removes
  the landmine instead of papering over it. Poison must bypass block, so
  `damageUnblockedHelper` (not `damage`, which subtracts block) is used; this
  matches the real game where poison damage is `DamageType.THORNS`.
- #57: `TimeEaterPlayCardQueueItem` copies `x` into a local `item`; the old code
  read the *currently queued* (triggering) card's exhaust flag, which corrupts
  card fidelity (e.g., Fiend Fire replayed after a non-exhaust trigger card
  avoided exhausting). The item's own `card` field is the replayed card.

## Alternatives considered

- Keeping `PoisonLoseHpAction()` parameterless and iterating all poisoned
  monsters inside the action — rejected: `Monster::applyStartOfTurnPowers`
  queues one action per poisoned monster, so a global iteration would tick
  poison N times when N monsters are poisoned. The explicit index restores the
  Java per-monster semantics.
- A runtime guard before the unconditional `actFunc()` call in
  `executeActions` — rejected in favor of implementing the stubs, since a
  guard would silently swallow future programming errors; the issue itself
  lists the stub implementation as the primary direction.
