# 2026-08-10 — issues 55, 58, 71 fixed (S3 leaf-cache stale obs, belief collapse default, PUCT value-only gate)

Date: 2026-08-10
Session/task: Investigator-audit bug-fix pass on `src/sim/search/BattleScumSearcher3.cpp`

## Decision

- **Issue 55 (depth-cap leaf cache serves wrong-world values):** the depth-cap
  direct-eval site in `BattleScumSearcher3::step` passed `cur->obsHash` to
  `evaluateLeaf`; `ensureObservation` sets that hash on the node's FIRST visit
  and never refreshes it, so a re-visit under a different determinization
  used the first world's hash as the `leafCache` key for the current world's
  `state`. The site now recomputes
  `CombatObservation::fromBattleContext(state).visibleHash()` fresh and passes
  that hash to `evaluateLeaf` (the same fresh hash is reused by the
  frontiergen hook, whose local redeclaration was removed). `ensureObservation`
  stays for the reuse-diagnostic mismatch tracking. The no-legal-action and
  invalid-edge direct-eval sites were audited and left unchanged.
- **Issue 58 (belief collapse):** `g_s3InternalBeliefUpdate` default flipped
  `true → false`. The default-on internal update was explicitly admitted
  "broken" in code — it zeroed mismatched particles inside `step()` until the
  root belief was destroyed within ~60 simulations and all sampling fell back
  to uniform (no resampling/rebirth exists). With the default OFF, the root
  belief keeps all particles alive through search; `STS_S3_INTERNAL_BELIEF_UPDATE=1`
  restores the historical behavior. This promotes the 64-seed GCP confirmation
  in `2026-08-09-internal-belief-fix.md` (win −3.1pp within discordance,
  floor +1.5, HP +1.4, cpu −8.9%): the fix was measured as correctness-
  preserving and is now the default.
- **Issue 58 (comment):** the stale comment in `ScumSearchAgent2::playoutBattle`
  claimed "In the fair path a fresh searcher/belief is built from the real
  state each decision, so no update is needed there." The fair S3 path
  (`playoutBattleFair`) actually carries one searcher/belief across decisions
  (advanceRoot + the `g_reuseMaxSearches` rebuild gate) and performs no
  boundary reweighting. The comment now says so and notes the carried belief
  can go stale between decisions (a documented limitation, not fixed here).
- **Issue 71 (PUCT gate missing `!g_pvnetValueOnly`):** both S3 PUCT selectors
  (`selectBestEdgePUCT`, `selectBestValidEdgePUCT`) now include
  `&& !g_pvnetValueOnly` in their `usePuct` conditions, matching S2
  (`BattleScumSearcher2.cpp:550-551, 589-591`) and S3's own
  `computeEdgePriors` gate. Previously `STS_PVNET_VALUE_ONLY=1` with no GBM
  left priors zero while PUCT stayed on → explore term ≡ 0 → every edge tied →
  always edge 0 (degenerate search). This resolves the open question in
  `combat-search.md` about whether value-only PVNet should disable PUCT
  recognition.

## Rationale

- #55: the leaf cache is keyed by visible state; the key must describe the
  state being evaluated. The node's cached hash describes a different world on
  re-visits. **Inference:** the fix changes only the cache key at the
  depth-cap site; values are recomputed when the hash differs, so cached-value
  correctness is restored and wrong-world values can no longer be served.
- #58: the default flip is the "candidate fix direction" in the issue (disable
  by default), not a resampling implementation; resampling stays an open
  research line. **Evidence:** `2026-08-09-internal-belief-fix.md` 64-seed
  confirmation and `2026-08-09-belief-audit.md` ("default 0").
- #71: consistency with S2 and S3's own prior gate; the value-only PVNet
  cannot produce priors, so it must not switch selection into PUCT mode.

## Alternatives considered

- #55: invalidate the cache key when a node is re-visited under a different
  world (e.g. refresh `node.obsHash` in `ensureObservation`) — rejected for
  the depth-cap site: the node's cached observation also feeds reuse
  diagnostics and `advanceRoot` obs-stability, which deliberately track the
  first-visit hash; recomputing locally at the eval site is the smallest
  correct change. (Revisiting the other direct-eval sites under a different
  world remains a possible follow-up audit.)
- #58: implement particle resampling/rebirth — rejected for now: a
  correctness-preserving default flip was already measured; resampling is a
  new mechanism needing its own design + paired gate.
- #71: leave PUCT on with zero priors — rejected: degenerate always-edge-0
  selection.
