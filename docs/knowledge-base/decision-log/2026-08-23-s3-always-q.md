# 2026-08-23 — Searcher3 immediate-Q exploitation diagnostic

## Decision

Stop the Searcher3 `STS_S3_ALWAYS_Q` experiment after the Phase A mechanism
diagnostic. Do not run gameplay validation from this task and do not retune the
flag.

## Evidence

The implementation was frozen at `96967bfb7276460f69dc1a5d11bd5bc345e9f5b8`
from baseline `f2879ad7d0444b4d3edad87ba62f6181580c48d8`. The flag is off by
default and changes only the existing exploit predicate used by both ordinary
and LIVE_VALID Searcher3 selection.

The paired Phase A run used seeds `93000–93007`, fair Searcher3, 64 particles,
300 live simulations per decision, and existing 250/500/1000/4000 root-race
probes. The control and treatment matched the 4000-simulation action at
91.8/92.6/93.0% for the three shallow budgets. Treatment did not improve the
hard elite subset, had slightly higher deep-reference regret, and consumed
416.26 vs 304.03 diagnostic CPU seconds (+36.9%). First-win simulation was not
available in the reused diagnostic and was not added after the negative result.

## Scope and uncertainty

The existing hook captured 208 ordinary and 48 Act-1 elite states but no boss
states, so this is not evidence about boss-specific behavior. The result is a
mechanism-level negative/stop decision, not a claim that immediate Q cannot be
useful under another configuration or budget.

Raw ignored outputs are under `build/phase_a/` in the task worktree. The
experiment ledger contains the exact flags, paths, metrics, and verdict.
