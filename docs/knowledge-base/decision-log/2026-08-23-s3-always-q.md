# 2026-08-23 — Searcher3 immediate-Q exploitation diagnostic

## Decision

Phase A is negative on the sampled ordinary/Act-1-elite corpus and does not
justify Phase B gameplay validation. Do not run gameplay validation from this
task and do not retune the flag.

## Evidence

The implementation was frozen at `96967bfb7276460f69dc1a5d11bd5bc345e9f5b8`
from baseline `f2879ad7d0444b4d3edad87ba62f6181580c48d8`. The flag is off by
default and changes only the existing exploit predicate used by both ordinary
and LIVE_VALID Searcher3 selection.

The paired Phase A run used seeds `93000–93007`, fair Searcher3, 64 particles,
300 live simulations per decision, and existing 250/500/1000/4000 root-race
probes. Each arm's shallow probes were compared with that arm's own
4000-simulation probe; this was not a shared deep teacher. Within-arm agreement
was 91.8/92.6/93.0% for both arms at the three shallow budgets. Treatment did
not improve the elite subset, had slightly higher deep-reference regret, and
consumed 416.26 vs 304.03 diagnostic CPU seconds (+36.9%).

## Scope and uncertainty

The existing hook captured 208 ordinary and 48 Act-1 elite states but no boss
states. First-win simulation was not recorded. The root-race files contain
run/decision metadata but no full visible-state hash, so exact control/treatment
state equality is unverified; rows are pairable only by
`(seed,floor,encounter,turn,decision_index)`. The experiment therefore did not
isolate no-win-yet, late-first-win, or boss/deep difficult roots. The narrower
late-first-win/no-win-yet mechanism remains **inconclusive**, not falsified.

Raw ignored outputs are under `build/phase_a/` in the task worktree. The
`tools/analyze_s3_always_q_phase_a.py` analyzer reconstructs the reported
root-race metrics and labels the 4000-simulation reference as arm-specific; its
self-test and raw-data run pass. The experiment ledger contains the exact
flags, paths, metrics, and verdict.
