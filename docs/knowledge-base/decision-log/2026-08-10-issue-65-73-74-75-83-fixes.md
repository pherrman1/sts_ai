# 2026-08-10 — issues 65, 73, 74, 75, 83 fixed (one_combat audit batch)

Date: 2026-08-10
Session/task: Investigator-audit bug-fix pass on `apps/one_combat.cpp`

## Decision

- **Issue 65 (Shop-V intercepts event/Neow/relic removals):** the
  `shopV && inRemoveSelect → removeSelectVPolicy` branch in `runFullRunOOC` is
  now shop-scoped: `shopV && gc.curRoom == Room::SHOP && inRemoveSelect`.
  `CARD_SELECT`/`REMOVE` is used by shop removal (`Shop::buyCardRemove`),
  Neow (`GameContext.cpp:2288,2343`), EMPTY_CAGE (1363), and events (Purifier,
  Ancient Writing); with `shopV=1` (always in bestbench/cpsictr/reprobench)
  all of those were routed to the shop-removal V-policy. `curRoom` stays
  `Room::SHOP` while the shop removal select is open, so this scopes the
  branch without a screen-state change. Event/Neow/relic removals now fall
  through to the default OOC policy. A comment documents the coupling.
- **Issue 73 (duplicate `winnettest`):** the second, unreachable `winnettest`
  mode branch (live full-run native-vs-server V_win parity check) was
  removed. The first branch (CSV-based tierb-schema validation that prints
  `rowidx,vwin` for the Python checker) remains the only `winnettest` mode.
- **Issue 74 (`datagen` STS_FAIR override):** the `datagen` positional-arg
  override `search::g_fairPlay = argc > 7 ? stoi(argv[7]) != 0 : false` now
  warns on `cerr` whenever the effective value differs from an `STS_FAIR` env
  var (including the no-positional-arg case where env `STS_FAIR=1` reverts to
  known-RNG). `datagen2`/`datagen3` still respect the env and are unchanged.
- **Issue 75 (`STS_WIN_NET` silent failure):** the `g_winNet.load(path, ...)`
  call in the `STS_WIN_NET` env block now checks its return value and logs
  `[STS_WIN_NET] failed to load win tree: <path>` on failure. The native-OOC
  fallback to `build/v_win_trees.txt` still applies (now visibly).
- **Issue 83 (datagen `pre` map share):** `runStrategicGenSeed` and
  `runStrategicGenSeed2` snapshot `pre` with
  `if (gc.map) pre.map = std::make_shared<Map>(*gc.map)`, matching the
  `detachedCounterfactualCopy` pattern. Previously `pre` shared the live
  run's map pointer and the live policy's `transitionToAct` in-place
  regeneration of `*map` could corrupt the snapshot. `pre` changed from
  `const` to non-const to permit the detach.

## Rationale

- #65: the shop-V removal model is trained on shop removals; applying it to
  Neow/event/relic removals applies an out-of-distribution policy.
  **Inference:** `curRoom == Room::SHOP` is the room check the issue's
  candidate direction asked for and is already maintained by `enterRoom`.
- #73: an unreachable branch is dead code with functional content; the live
  parity check it contained has no caller path.
- #74: silent regime switches between env and positional config are the
  exact hazard class the project-fair/known-RNG separation rules warn about.
- #75: a missing model artifact is not evidence of a loaded model
  (AGENTS.md trap); logging makes the fallback visible.
- #83: mirrors the already-closed probe→live direction; the decision log
  `2026-08-09-strategic-datagen-shared-map-detach.md` left the live→snapshot
  direction open.

## Alternatives considered

- #65: route removals by screen type alone (impossible — REMOVE is shared);
  a broader refactor of `removeSelectVPolicy` to detect shop context itself —
  rejected as larger scope than the room check.
- #73: rename the second branch to a distinct mode name — rejected: it
  duplicated the CSV `winnettest` intent via a v_server socket and nothing
  invoked it; deletion is smaller.
- #83: switch both sites to `detachedCounterfactualCopy(gc)` — equivalent,
  but the plan's explicit `pre.map = make_shared<Map>(*gc.map)` detach was
  kept with the guard matching line 4845's helper.
