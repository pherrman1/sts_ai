# 2026-08-10 — Fix issues 54 and 70 (Searcher2 convroot hang, stale outcome on re-expansion)

Date: 2026-08-10
Session/task: Implement fixes for issues #54 and #70 from
`docs/knowledge-base/issues/`.

## Decision

Apply two `BattleScumSearcher2` fixes and add one combined regression test.

- **#54** `searchToTotalRootStable`: guard the chunk loop — when
  `budget <= root.simulationCount` (zero-start or zero-growth config), set
  `budget = targetSimulations` so the search always makes progress instead of
  spinning forever. `apps/one_combat.cpp` additionally prints a parse-time
  warning when `STS_CONV_ROOT` is on with `STS_CONV_ROOT_START<=0` or
  `STS_CONV_ROOT_GROW<=1.0`.
- **#70** `step()`: clear the node's stale `outcome` (set to `0`) right before
  re-enumerating edges in the leaf branch, so a node that was terminal in a
  previous determinization (outcome != 0, empty edges) but is non-terminal in
  this world does not keep the stale outcome. This preserves the documented
  invariant "outcome != 0 implies edges.empty()" and keeps
  `collectFrontierStats` from misclassifying the node as a terminal leaf.

## Rationale

- **#54** the growth formula
  `budget = min(target, llround(budget * g_convRootGrow))` never raises the
  budget when `g_convRootStart == 0` or `g_convRootGrow <= 1.0`, so
  `chunkEnd == budget` and the inner loop runs 0 steps while the outer loop
  spins forever. Forcing the full budget is the smallest change that
  guarantees termination; the parse-time warning surfaces the misconfig
  instead of silently running a flat budget.
- **#70** the in-tree terminal check sets `outcome` and returns without ever
  expanding terminal nodes, so in fair mode (per-sim determinization) a node
  terminal in one world keeps `outcome != 0` with empty edges; when another
  world reaches the same tree node non-terminal, the leaf branch re-enumerates
  edges while the stale outcome survives. The unconditional reset is safe: any
  node entering the leaf branch is non-terminal in the current world (the
  terminal check above returns first), so a pre-existing non-zero outcome is
  always stale there.

## Alternatives considered

- Validate `g_convRootStart > 0 && g_convRootGrow > 1.0` at parse time and
  abort — rejected: the guard makes any config terminate, and a hard failure
  would break downstream scripts that set the vars without `STS_CONV_ROOT`.
- Skip re-expansion of previously-terminal nodes — rejected: the state is
  genuinely non-terminal in the current world, so re-expansion is the correct
  behavior; only the stale flag is wrong.
