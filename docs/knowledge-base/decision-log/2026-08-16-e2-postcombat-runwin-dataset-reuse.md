# E2 post-combat run-win critic: dataset reuse

Date: 2026-08-16
Status: accepted for the E2 diagnostic

## Decision

Use the existing ignored `build/vrich.csv` for E2 rather than adding a C++
producer. Its producer (`datagen2`) emits one canonical rich-state row at the
first card-reward decision after a survived normal, elite, or act-1/2 boss
combat. The row is emitted after the fixed gold/relic/potion auto-pickup and
before the card pick/skip. `won` is buffered until run termination and is the
eventual run outcome.

## Evidence and limits

The current tree verifies the lifecycle as:
`BattleContext::exitBattle` commits persistent combat effects, victory calls
`GameContext::regainControl`, and `afterBattle` opens the combat reward screen.
Combat rewards always contain a card reward. Act-3 terminal boss fights and
event-room fights do not provide this row boundary and are consequently not
represented.

The dataset was generated by `tools/run/datagen2_loop.sh` on 2026-07-15 at
ascension 0, 10,000 simulations, epsilon 0.05, with the V-marginal server card
policy. The rich vector is produced by the canonical `vFeatCsv`/`richRow`
path; it is not duplicated in the trainer. It includes simulator known-RNG
encounter/progression fields, which are predictive features rather than causal
variables.

E2 uses seed-grouped `GroupShuffleSplit(test_size=0.15, random_state=0)` and
matched B0/B1/T evaluation. B1 is `curHp`, `maxHp`, `hpFrac`, `act`, `floor`.
T is every non-label, non-constant column in the rich schema using the
`train_winrate.py` XGBoost recipe. This decision establishes predictive
diagnostic methodology only; it does not authorize Searcher3, V_combat, or
gameplay integration.

## Relation to §116 and correction before merge

§116 recorded a null TERM_WIN terminal-leaf benchmark: the deployed win tree
was insensitive to counter features, so the counterfactual terminal-value
stage was deferred pending a counter-aware evaluator. E2 potentially satisfies
that previously missing *prerequisite* in the limited sense that it provides
an offline post-combat run-outcome critic with rich state information. It does
not demonstrate a counter-aware terminal evaluator, causal counter pricing, or
that TERM_WIN/Searcher3/V_combat should consume it.

The initial E2 artifact bootstrapped sparse full-dataset run IDs for validation
rows. Before merge, the trainer was corrected to reindex validation run IDs
contiguously; the full offline bootstrap and recorded numbers were regenerated.
This correction changes uncertainty estimates, not fitted models or held-out
predictions.
